# Localization

The UI is available in English (`en`), Portuguese (`pt`) and Spanish (`es`), using [react-intl](https://formatjs.github.io/docs/react-intl).

## How the locale is chosen

Every page lives under a locale segment: `/en`, `/pt/tasks/new`, `/es?q=report`. `src/proxy.ts` redirects any URL without one, picking the locale in this order:

1. The `NEXT_LOCALE` cookie, set by the language menu in the header.
2. The browser's `Accept-Language` header (`matchLocale` in `src/i18n/config.ts`).
3. English.

The API (`/api`), Next internals and files with an extension are not redirected. Unknown paths under a locale (`/es/nada`) show the localized 404 via `app/[locale]/[...rest]`.

`app/[locale]/layout.tsx` is the root layout. It sets `<html lang>`, and its `generateStaticParams` gives each locale its own prerendered shell.

## Translating

| Where | How |
| --- | --- |
| Server components | `const intl = await getIntl()` from `@/i18n/server`. The locale comes from `next/root-params`, so nothing is passed down. |
| Client components | `useIntl()` or `<FormattedMessage>` from `react-intl`. |
| Links | Write locale-free paths. `LinkButton` and `PageBreadcrumbs` prefix them; elsewhere use `useLocalizedPath()` from `@/i18n/client`. |
| Validation | `taskInputSchema` messages are message ids. Show them with `useTranslateMessage()`. |
| tRPC errors | `useErrorMessage()` maps `NOT_FOUND` and message ids to text, and anything else to a generic message. |
| Dates | `intl.formatDate(date, { dateStyle: "medium", timeStyle: "short" })`. |

## Adding a string

1. Add the key to `src/i18n/messages/en.ts`.
2. Add the same key to `pt.ts` and `es.ts`. A missing key fails `pnpm typecheck`, because both are typed as `Messages`.
3. Use it. Message ids are type-checked through the `FormatjsIntl.Message` declaration in `messages/index.ts`, so a typo fails `pnpm typecheck` too.

`src/i18n/i18n.test.ts` also checks that all catalogs have the same keys and that every message formats.

Messages use ICU syntax, e.g. `"list.noMatches": "No tasks match “{search}”."`.

## Adding a language

1. Add the code to `locales` and a name to `localeNames` in `src/i18n/config.ts`.
2. Create `src/i18n/messages/<code>.ts` typed as `Messages` and register it in `messages/index.ts`.

The proxy, static params, language menu and tests pick it up from `locales`.
